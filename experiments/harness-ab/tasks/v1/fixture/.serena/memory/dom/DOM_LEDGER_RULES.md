# DOM_LEDGER_RULES — ledgerlite Domain Rules

Authoritative business rules for ledgerlite. These rules are NOT restated in task
prompts — implement exactly what is specified here.

## Amount Parsing

- Amounts are decimal strings (e.g. `"12.34"`, `"-5"`, `"0.5"`) parsed to integer cents
  via `Decimal`. Anything that does not parse to a whole number of cents raises
  `LedgerError(E_INVALID_AMOUNT, ...)`.
- Negative `amount_cents` = expense. Positive = income.

## Categories

- Fixed allowed set: `groceries`, `rent`, `utilities`, `transport`, `dining`, `salary`,
  `other`. Any other category raises `LedgerError(E_UNKNOWN_CATEGORY, ...)`.

## Recurring Rules

- `RecurringRule.frequency` must be one of `weekly`, `biweekly`, `monthly` exactly.
  Any other value raises `LedgerError(E_BAD_FREQUENCY, ...)`.
- `RecurringRule.end`, if set, must not be earlier than `start`. `end < start` raises
  `LedgerError(E_BAD_DATE_RANGE, ...)`.
- IDs for recurring rules are `r1`, `r2`, … — the next id is `max(existing numeric
  suffixes) + 1` (same scheme as transaction ids, but with the `r` prefix).

### Occurrence Expansion (`occurrences(rule, window_start, window_end)`)

The window `[window_start, window_end]` is INCLUSIVE on both ends.

- `weekly`: an occurrence every 7 days starting from `rule.start`.
- `biweekly`: an occurrence every 14 days starting from `rule.start`.
- `monthly`: one occurrence per calendar month, on the same day-of-month as
  `rule.start`, clamped to the last valid day of each target month when that month is
  shorter. Clamping NEVER shifts the anchor day going forward — e.g. an anchor of the
  31st clamps to Feb 28 (or Feb 29 in a leap year) for February, but March's occurrence
  is still on the 31st (the anchor day is re-evaluated per month from `rule.start`'s
  day-of-month, not carried forward from the previous clamped occurrence).
- Only occurrences that fall within `[window_start, window_end]` are returned, and only
  those on or after `rule.start` and (if `rule.end` is set) on or before `rule.end`.
- Returned dates are sorted ascending.

## Budgets

- `budget_report(store, month)` returns one `BudgetLine` per category that has a budget
  set for `month`, sorted by category name ascending.
- `month` must match `YYYY-MM` with month `01`–`12`; anything else raises
  `LedgerError(E_BAD_MONTH, ...)`.
- `spent_cents` = sum of the ABSOLUTE VALUE of all expense amounts (i.e.
  `amount_cents < 0`) in that category and month, INCLUDING amounts generated by
  expanding every recurring rule's occurrences that fall in that month (a recurring
  rule with a negative `amount_cents` contributes `abs(amount_cents)` per occurrence in
  the month). Income (`amount_cents > 0`, e.g. `salary`) is NEVER included in spend,
  even if a budget exists for that category.
- `remaining_cents` = `limit_cents - spent_cents` (may be negative when over budget).
- `status` thresholds, evaluated as `spent_cents / limit_cents`:
  - `ok`      — spent < 80% of limit (strictly less than 0.8)
  - `warning` — 80% ≤ spent ≤ 100% of limit (inclusive both ends)
  - `over`    — spent > 100% of limit (strictly greater than 1.0)
- A category with a budget set but zero spend in that month still appears in the
  report, with `spent_cents = 0` and `status = "ok"`.
- A category with NO budget set for that month does not appear in the report at all.

## Schema v2 Migration

- On `Store.load()` of a file with `schema_version: 1`, before rewriting:
  1. Write a byte-identical backup copy of the original file to `<path>.v1.bak`.
  2. Add `"recurring": []` and `"budgets": {}` top-level keys (unless already present).
  3. Set `"schema_version": 2`.
  4. Preserve every other unknown top-level key from the v1 file untouched (do not drop
     or rename anything not explicitly part of the v1/v2 schema).
- Loading an already-v2 file is a no-op with respect to migration (idempotent — loading
  twice does not create a second `.v1.bak` or duplicate data).
- Budgets are stored as `{"YYYY-MM": {"category": limit_cents}}`.
- Recurring rules are stored as a list of objects mirroring `RecurringRule` fields
  (dates as ISO strings, `end` as `null` when unset).
